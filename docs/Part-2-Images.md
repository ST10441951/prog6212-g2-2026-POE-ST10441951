# RaceDay Part 2 - Images

## 1. Endpoints and access

| Method | Route | Success |
|---|---|---|
| PUT | `/api/profile/picture` | 200 with `profilePictureUrl` |
| DELETE | `/api/profile/picture` | 204 with no body |
| PUT | `/api/events/{eventId}/banner` | 200 with `bannerImageUrl` |
| DELETE | `/api/events/{eventId}/banner` | 204 with no body |

Pictures require a Participant session. The account ID comes from the session. Banners require an Organiser session and ownership of the event. Missing or expired sessions return 401, wrong roles and other owners return 403, and missing events return 404. An inactive account first receives 403 and its session is revoked; later requests receive 401 (Microsoft, 2026a).

## 2. Image checks

PUT accepts exactly one `imageFile` in `multipart/form-data`, with no extra form fields. JPEG uses `.jpg` or `.jpeg` and `image/jpeg`; PNG uses `.png` and `image/png`. The decoded format must match the extension and MIME type (Microsoft, 2026b).

- Input and processed files must each be at most 5 MiB. Larger files return 413. The whole multipart request allows another 64 KiB for form headers. A resource filter checks the body before form binding, including streamed requests, so an oversized body also returns 413 (Microsoft, 2026i; 2026j).
- Each side must be at most 4096 pixels, with no more than 64 MiB of decoded RGBA pixels.
- Empty, damaged, animated or oversized-dimension images return 400.
- Unsupported types and content mismatches return 415. JSON is not accepted for uploads.
- SkiaSharp inspects the header and decodes the full image before it is re-encoded without the original metadata or trailing data. JPEG uses quality 90. At most two decoders run together (Microsoft, 2026c; 2026d).
- File names are generated by the API. Client paths, account IDs and blob names cannot select the stored object.

PNG animation is checked through its chunk structure (W3C, 2025).

## 3. Storage and saved records

The Azure Blob SDK uploads streams to a private `raceday-images` container. An existing public container is rejected. SQL stores only the generated name in the existing User or Event column. The seven-table schema and migration are unchanged (Microsoft, 2026e).

Responses use a blob-specific, read-only SAS URL valid for one hour. The account key stays in API configuration. Profile reads, event details and public and owned event lists generate fresh URLs. Missing images return null. URLs are not stored in SQL. Only names generated in the API's picture and banner paths are exposed through these URLs (Microsoft, 2026f).

Replacements upload the new object before saving its SQL name, then remove the previous object. A failed SQL save attempts to remove the new upload and keeps the old name. Cleanup failures are logged with the object name for retry. SQL and Blob Storage do not share a transaction.

Removal deletes the object, clears its SQL name and sets the UTC update time. Repeating DELETE returns 204. If storage fails, the API returns 503 and keeps the saved name for retry. If SQL fails after blob removal, repeating DELETE clears the now-missing object reference. Unavailable or invalid storage configuration returns 503 for uploads. No credentials are returned in errors.

Picture changes lock the account row. Banner changes and event deletion use the shared event update lock. Competing requests therefore preserve the saved image link and prevent a banner being attached to a deleted event (Microsoft, 2026g).

## 4. Setup

For local work, install Node.js with npm and run the emulator from the repository folder in a separate terminal (Microsoft, 2026h).

```text
npx --yes --package azurite@3.37.0 azurite-blob --blobHost 127.0.0.1 --location .azurite --silent
```

Development settings use `UseDevelopmentStorage=true` and container `raceday-images`. The emulator listens on `127.0.0.1:10000`; its files are ignored by Git. Start it before using images or running the tests.

For an Azure account, set `ImageStorage__ConnectionString` privately through environment settings or user secrets. It must be an account-key connection string with access to a private container. Set `ImageStorage__ContainerName` if using another container. Keep real keys out of committed files. Outside Development, image storage must be configured separately.

Tests use their own `raceday-tests-...` container and temporary SQL database. `RACEDAY_TEST_STORAGE_CONNECTION` can select a separate test account; the fixture still chooses and removes only its own container. The default is local Azurite. The GitHub workflow installs and starts the pinned emulator before running all tests.

All 810 tests pass locally with none skipped, including 76 image checks. The build has no warnings or errors, the planning checks pass and no model changes are pending. The dependency audit reports no known vulnerable application packages.

Checks cover all four operations, JPEG and PNG, readable signed URLs, denied unsigned reads, SQL persistence, replacement, removal, expired and inactive sessions, wrong roles, event ownership, invalid files and form fields, metadata removal and dimension limits. Failure checks cover storage settings, upload and removal failures, failed SQL saves and retried removal. Concurrent requests check picture replacement and banner upload against event deletion.

The Swagger operation list is compared directly with all 40 method-and-route pairs in the corrected endpoint plan. Image inputs are described as binary multipart fields.
